## §0 Frame-fit gate

The eligible frame is the **object-level claim corpus**: observations and derivations whose claim is about the world / the work, NOT about ENGRAM's own confidence-scoring machinery.

**Meta-discourse GATE — mechanical (draft-10; Kepler's call as co-signatory, folding Aleph's instrument-separation principle; his signature extends to this amendment).** The GATING exclusion is Study-2b's deterministic **regex metadata-screen + >20%-gutted-exclusion** pre-filter, reused here (Luria code-verified it is chain-scoped + mixed-population, so it maps onto track-b's derivation packets over the claim + premise-claim surface). A mechanical gate is REQUIRED for **instrument-separation**: a classifier-based exclusion (the earlier construct/topic criterion, dv_1085) would put gatekeeping INSIDE the measured judge — a judge-dependent denominator + exclusion↔typing correlation through the shared model, the same failure class as §2's confidence-leak and §5's self-grading concern. The mechanical gate is deterministic, judge-independent, and runs pre-frame; the excluded set is identical regardless of which judge scores.

**Construct/topic criterion → REPORTED sensitivity annotation, NOT a gate.** Leak-density is a *proxy* for meta-discourse, not its definition: a machinery-TOPIC node with few redactable spans passes the mechanical gate yet is still circular to score. So — per stratum, and run AFTER typing so it cannot influence the judge — we report how many gated-IN nodes a topic-screen would have flagged. If ~0, the proxy was sufficient and we say so; if material, that is a **pre-registered sensitivity analysis**, not a reviewer's gotcha. Exclusion counts + rates reported per stratum at freeze. If an exclusion guts a cell below the power floor (§4), that is itself a reported finding.

## §1 Research question + hypotheses

**RQ.** ENGRAM's confidence is a near-mechanical map from a *chosen type* (quote_type for observations, reasoning_type for derivations). Study-1 found the miscalibration is not in the within-type arithmetic (within-type AUC ≈ 0.49 null) but in the **type-selection step** (raw AUC 0.378 anti-H1). Two independent witnesses now point at type-selection: Study-1's refuted *observations* (quote_type) + Aleph's dv_0183 retraction audit (8/8 *derivation* retractions were reasoning_type-choice errors). Track-(b) tests type-selection miscalibration **directly**, on both type systems.

**H1 (primary, falsifiable, negative publishes).** Nodes whose agent-chosen type DIVERGES from the panel-warranted type retract/supersede-as-wrong at **higher odds** than concordant nodes — estimand: the **odds ratio, OR > 1** (§5 M2; §4's case-control outcome-stratified sampling identifies the OR, not the marginal rate). (The calibration link: overreach in type-selection → later refutation.)

**H0.** Divergence does not predict outcome (divergence rate equal across refuted vs survived). A null is a real result and is reported as-is.

**Secondary (S1).** Divergent nodes are enriched for interpretive/predictive claim-text features (the cs_0047 "generalizing-language tell"); i.e. an automatable filing-time detector would have flagged the divergent set. (§6.)

**Secondary (S2, generality).** The type-selection failure is agent-GENERAL, not Borges-specific: divergence→outcome holds across ≥2 consenting agents' graphs. (Enabled by the multi-graph population, §4.)

## §2 Design — blind re-classification, NORMATIVE instrument, dual axis

**The instrument is NORMATIVE, not replicative (dv_1083 — the load-bearing design decision).** The judge does NOT answer "would a blind agent make the same type choice from the same inputs?" (replicative — that scores the dv_1071 failure class as *concordant* and misses it, because the quote is genuinely hard_data while the CLAIM over-reaches it). The judge answers **"what is the strongest type this CLAIM is warranted in, given only this evidence?"** (normative). Divergence = the agent asserted a stronger type than the claim-vs-evidence warrants — which IS the failure.

Consequence pre-registered (Kepler rider 1): the normative reading makes the H1 outcome-link *cleaner* (overreach → refutation is exactly the causal story), and it means **the study's judge and any future production filing-gate see DIFFERENT inputs** — the judge withholds `interpretation`; a filing-time gate necessarily runs WITH interpretation present. This input-gap is registered NOW so a later "the production gate under/over-performs the study judge" result is read as the expected consequence of different inputs, not a failure.

**Observation arm — dose.** Judge sees: `claim` + `quoted_text` + `source_class` + `source_domain` + `source_date`. **Withheld:** agent's chosen quote_type, confidence, outcome, node id, filing-agent, and — critically — the agent's `interpretation` field (the agent's own reach-justification = the framing leak). Judge assigns the warranted quote_type from the verbatim type definitions (§below).

**Derivation arm — dose.** Judge sees: `claim` + each premise's `claim` text + each premise's `type`. Assigns the warranted reasoning_type. (Already normative: reasoning_type is a property of the visible premise→conclusion structure, so re-typing here needs no reframe — dv_1083.) **Withheld:** agent's chosen reasoning_type, confidence, outcome, node id, filing-agent.

**Type definitions.** Judge receives the type definitions from the tool schemas — we test the *choice*, not the docs. Definitions order-randomized per item. **Confidence-redaction of the reasoning_type definitions (blinding enforcement, Luria build-catch):** unlike quote_type's clean bare-enum, the reasoning_type schema text (engram_derive docstring) carries INLINE confidence discounts ("deductive (discount 0.98)", "abductive (cap 0.80)", …). Reproducing it truly verbatim would leak the confidence anchor §2/§3 withhold. So the derivation-arm definitions are **confidence-redacted before rendering**: the type's *inference-form semantics* are preserved verbatim (e.g. "corroborative, multi-source" — the actual warrant requirement the judge must assess), while the *confidence-derivation* framing is stripped (the numbers AND the mechanism/hierarchy words "discount"/"cap"/"weakest form" — same downstream-anchor class as the numbers). Mechanical redaction of the confidence-annotation spans, NOT a hand-written paraphrase (which would be the invent-definitions anti-pattern + risk altering the tested semantics). Residual: after stripping the mechanism-words, no "discount-vs-cap"-shaped type-discrimination remains (that shape-leak is why number-only redaction is insufficient). This is a specific enforcement of the §Blinding-integrity "no confidence anywhere in the packet" rule, applied to the definitions themselves. **Registered input-gap (Kepler rider, parallel to the interpretation-withholding gap above):** the filing agent saw the full inline-discount docstring at choice-time; the derivation-arm judge sees strictly LESS — warrant-relevant semantics only, confidence anchor redacted. So the judge receives the *same warrant-relevant information* the filer had, NOT literally "the same information." This is deliberate and correct under the normative instrument (we score warrant, not choice-replication; the confidence anchor is precisely the withheld variable), and it is registered NOW so a reviewer reading §2 against the redaction sees a NAMED, intended gap — not an unacknowledged contradiction. A later "production filing-gate (which runs with the anchors visible) diverges from the study judge" result is thus the expected consequence of different inputs, same logic as the interpretation gap.

**Blinding integrity.** No confidence anywhere in the packet (enforced at the data layer: frame ships as `{id, claim, evidence_fields, stratum}` with NO confidence/type/outcome field — dv_1081). Recursive strip (confidence hides in warning text, edge metadata, recall summaries — Study-2 pin). As-of-filing-time reconstruction where any post-filing correction could leak the outcome (Study-2 temporal-cutoff pin, load-bearing for the refuted stratum).

## §3 Judge panel + κ gate (instrument validation FIRST)

There is no ground-truth "correct type" — type assignment is itself a judgment. A single judge measures "agent disagreed with this one model," not "agent was wrong." So the panel does double duty (dv_1074 pin-3 "validate the instrument first," made a pre-registered gate):

1. **De-confound** family-idiosyncratic definition-reading (cj_0001 shape).
2. **Inter-rater denominator.** Only nodes where the panel is **concordant among itself** (majority agreement) are eligible to score agent-divergence. Panel-**discordant** nodes → a separate **"type genuinely ambiguous"** bucket, reported as its own estimand (it bounds how much of Study-1's signal is real mis-selection vs. irreducible type-ambiguity).

**Panel:** ≥3 judges (odd, for a clean majority), ≥2 lineages (see §7 for the provider scoping this depends on). **Instrument-validity floor: Fleiss κ ≥ 0.60** (Landis-Koch "substantial") across the panel, committed as a number pre-data (Kepler rider 2). If κ < 0.60, the type system is too ambiguous to score agent-divergence reliably, and **we report that** as the primary result rather than proceeding to H1.

**Metric-0 (pre-registered):** report the panel's Fleiss κ per type system, and the panel-discordant ("ambiguous") fraction per stratum, BEFORE any H1 analysis.

## §4 Populations + power (MULTI-GRAPH, measured — ob_2805)

**Population = multi-graph, REQUIRED not optional.** Measured on my frozen graph (engram-frozen-2026-07-04.db): calibration-relevant refuted observations ≈ 29-48 (workable single-graph), but calibration-relevant refuted **derivations ≈ 14** (thin — underpowered single-graph). So the reasoning_type arm **requires aggregation** across consenting agents' frozen snapshots; single-graph would leave the derivation arm underpowered. This also delivers S2 (generality) for free: agent-identity becomes a *feature* (is the failure agent-general?), not a confound — the judge strips filing-agent regardless.

**Derivation-arm power RISK — sharper than ob_2805 (Aleph's reasoning-arm review, ob_2812).** Aleph audited his frozen graph: **9 derivation retractions, ALL `error_type=other` and ALL reasoning-type-choice / premise-independence / confidence-propagation mis-types** — so under the §4 boundary his QUALIFYING refuted-derivation count is **≈0** (all 9 fall in the *excluded* `excluded_type` class; zero hallucinated/wrong_evidence/contradicted-lost/claim-false). If derivation retractions are type-error-DOMINATED in general, the `excluded_type` exclusion strips ~100% of derivation retractions per agent, and multi-graph aggregation of near-zero-each could STILL starve the reasoning_type arm's agent-divergence estimand. Two pre-freeze consequences, both registered: (a) **re-measure my own ≈14** under the strict `excluded_type` exclusion (ob_2805's count predates this boundary — it may collapse toward Aleph's ≈0); if it does, the derivation arm's H1/M2 on the *primary* refuted population is reported UNDERPOWERED, which per §0 is itself a finding, not a failure. (b) The **positive-control M5 (§5) recovers derivation-arm value regardless of (a)** — it runs on the ABUNDANT `excluded_type` set (Aleph alone: 9), turning the starved primary population into a validated instrument. **Pre-freeze ballpark (ob_2816 — my live graph, eyeball classification, NOT the registered blind-labeler pass): my qualifying count ≈ 8-15 vs Aleph's ≈ 0.** This raw-COUNT gap does **NOT** establish agent-heterogeneity (Lei, correcting my initial "agent-variable" read — an absolute-vs-rate confound): my graph is ~5× larger (~5500 vs ~1000 nodes), so equal *rates* still yield ~5× the count; and Aleph's 0 is a small-sample zero (~9 derivation retractions), whose CI is wide (rule-of-three upper bound ≈ 3/9 of retractions) and fully consistent with a non-trivial rate. **Rate-normalized with CIs, the two are statistically indistinguishable at current N — agent-heterogeneity is UNPROVEN (neither established nor excluded).** The correct consequence for the design: the derivation arm is a **rare event with small per-graph N**, so multi-graph aggregation is required for POWER (aggregate sample size), *independent of* whether agents' rates actually differ — that sample-size argument is the robust one; the earlier "agent-variable, what multi-graph captures" framing over-read absolute counts and is retracted. A conclusive per-agent rate comparison itself needs larger graphs. (History caveat, Lei: a real per-agent difference *could* exist — my ENGRAM/paper work gets high-rigor review, Aleph's financial work less-deep review from Lin, which could shift caught-error rates — but this is confounded with N and undisentanglable now.) M5's positive-control value is unaffected (it draws on the `excluded_type` set regardless of the rate question). The registered blind-labeler pass at freeze produces the rate + CI, not a raw count. The observation arm is unaffected (its refuted population is workable per ob_2805).

**Refuted-set boundary — by the error_type taxonomy** (the 6 retraction types, ob_0007):
- **INCLUDE** (calibration-relevant = claim/reasoning was wrong): `hallucinated_claim`, `wrong_evidence`, `fabricated_quote`, `other` — **but** an `other`-retract that is really a *type-fix* (retracted then re-filed with the SAME claim but a DIFFERENT type) is `excluded_type`, NOT INCLUDE (screened by the labeler below, Aleph ob_2812); plus contradicted-and-lost (structural, off `resolves` provenance) and superseded-**as-wrong** (blind as-wrong/as-refined split per Study-1 rubric).
- **EXCLUDE**: `duplicate` (housekeeping — claim wasn't wrong), `wrong_citation` (provenance error — claim may be fine), and superseded-**as-refined** (evolution, not refutation), and **type-errors** (claim true, type wrong) — the `excluded_type` class. Type-errors surface TWO ways and the labeler must catch BOTH (Aleph ob_2812, from his ledger): a formal `supersede`, OR — the DOMINANT form in practice — a **`retract` (error_type=`other`) + corrected re-file** (same claim, different type; the retract codes carry no type slot, so a mis-typed derivation is fixed by retract-and-refile more often than by a formal supersede). A supersede-**only** detector both undercounts M5's positives AND leaks type-errors into the INCLUDE/`other` population above — a **circularity leak**, since type-selection is the study's PREDICTOR and cannot also be its outcome. Excluded here; harvested as M5's positive-control (§5).

**Outcome-labeling stage — the as-wrong/as-refined split is a DISTINCT BLIND EXOGENOUS LABELER PASS, not a stored field, not the author, not the type-judge.** The 4 mechanical INCLUDE types are `metadata.error_type` on a retracted node (no judgment). But `supersede` records no wrong-vs-refined field — the split is a judgment over (`old_claim`, `new_claim`, `supersede_reason`). It MUST be a blind exogenous labeler (raw-API, rubric-only — the same dispatch machinery as the type-judge, different rubric and target), **NOT the author**: an author reading their own supersede reasons to decide "was I wrong or just refining?" is the same-standpoint self-check the study exists to measure, judging itself (the dv_1069 exogeneity requirement). It is **independent of and blind to the type-judge** — neither pass sees the other's output; outcome and type are separate measurements. Runs on the frozen population; superseded nodes **and `other`-retracts** are **never silently dropped** — each flows through the labeler (an `other`-retract is additionally checked for a same-claim-different-type re-file → `excluded_type`, per Aleph ob_2812), tagged `unclassified` until resolved to `refuted` (INCLUDE) / `survivor_refined` (EXCLUDE) / `excluded_support` / `excluded_type`. **Rubric (Study-1, load-bearing):** (a) *false-NOW ≠ false-AT-FILING* — a claim correct-at-filing that became false via a later decision/restructure/premise-reversal is `survivor_refined`, not refuted; (b) `refuted` IFF the reason asserts the OLD claim's CONTENT was incorrect-at-filing; (c) `survivor_refined` IFF the reason describes narrowing/extending/re-scoping/vocabulary/nuance to a claim correct-then; (d) DEFAULT (empty/non-committal reason) → `excluded_support`; (e) old≈new claim (semantically equivalent) → `survivor_refined` (metadata/confidence changed, not content); (f) `excluded_type` IFF the correction — a `supersede`, OR a `retract`+re-file with the same claim and a different type (Aleph ob_2812: the dominant form) — fixed the node's TYPE/classification (should have been a different node type, or wrong quote_type/reasoning_type) while the claim content stood — the **circularity guard** (a type-error cannot count as the outcome when type-mis-selection is the predictor); tracked distinctly for exclusion-accounting AND harvested as M5's positive-control (§5), though it collapses to EXCLUDE for the outcome variable. So the labeler emits **four** categories: `refuted` (INCLUDE) / `survivor_refined` / `excluded_support` / `excluded_type` (latter three EXCLUDE). Harness stage (builder's lane); rubric author-provided.

**Strata.** Outcome (refuted vs survived) × fs_class (re-executable vs frozen) × type system. Over-sample the refuted stratum (rare, high-information).

**Right-censoring.** Nodes filed near each graph's freeze have unrealized outcomes — flagged and handled as Study-1 (they enter the divergence-rate denominator but not the outcome-link numerator unless resolved before freeze).

**Consent.** Per-graph, per the data-ownership precedent (each agent owns their graph): Kepler in; Borges in; Ariadne, Aleph, others by explicit consent. Each contributes their own frozen snapshot; no live graphs. Consent covers BOTH uses of a graph's retraction/supersede history: the scored divergence population (M1-M4) AND the `excluded_type` positive-control set (M5). Aleph in for both (his review supplied the 9-node positive-control seed).

## §5 Metrics (pre-registered estimands)

- **M0 — instrument validity:** Fleiss κ per type system; panel-ambiguous fraction per stratum (§3).
- **M1 — divergence rate + confusion matrix** per type system (which type-pairs confuse — e.g. attributed_analysis filed as official_statement; single-premise inductive_generalization filed where modus_ponens floors weaker). Eligible = panel-concordant nodes.
- **M2 (H1) — divergence predicts outcome, as an ODDS RATIO** (Kepler countersign amendment): the **OR of refutation for divergent vs concordant nodes** (+CI); **pre-committed direction OR > 1.** §4's outcome-stratified sampling (over-sampling the refuted stratum) is a **case-control** design — you sample ON the outcome, so the marginal rate ratio is NOT estimable, but the OR **is** (and is what case-control identifies). The OR is direction-symmetric, so it also **dissolves the H1 (cohort-framed "higher rate") / H0 (case-control-framed "divergence rate equal across outcome") mismatch** — the single estimand OR > 1 tests both directions at once. Null (OR CI spanning 1) publishes.
- **M3 — implied-confidence delta:** if the panel-warranted type had driven the confidence map, how much and which direction does confidence move on the refuted set (quantifies the miscalibration in confidence units).
- **M4 (S2) — generality:** M2's **OR** computed per-graph + pooled (fixed/random-effects meta-analytic pool); report whether the divergence→outcome **OR > 1** holds across ≥2 agents.
- **M5 (instrument positive-control — Aleph, ob_2812) — panel recovers agents' own type self-corrections.** The `excluded_type` set (§4: type-error supersedes, held OUT of the M1-M4 divergence population for circularity) doubles as a **ground-truth positive-control**: each is a case where the agent self-corrected a node's type post-hoc (filed X → corrected to Y via EITHER a formal `supersede` OR — the dominant form, Aleph ob_2812 — a `retract`+re-file with the same claim and a different type; the pre-correction type is recoverable from the retracted/superseded node, `is_current=0` but queryable). Reconstruct the pool from BOTH forms, not supersede-only — a supersede-only miner undercounts precisely where the primary arm is already starved. Hand the blind panel the PRE-correction derivation — a valid warrant-judge should diverge from the agent's *original* type and land on (or toward) the agent's *own correction*. Report the **panel-recovers-the-correction rate** alongside Fleiss κ (§3/M0): it validates the instrument with real positives exactly where the primary agent-divergence pool is starved (the §4 derivation-arm risk). Strictly non-circular — the positive-control set is excluded from M1-M4, so no node is ever both predictor and outcome. Pre-committed direction: recovery-rate > chance (chance = 1/#candidate-types). **Gating:** if the panel CANNOT recover known self-corrections, the warrant-judge is not measuring warrant and M2 divergences carry no weight — reported as-is, alongside M0.
